## 2. Crest 的架构（最值得抄的部分）

Crest 不是一个 shader，是**一套分层的系统**。核心分层：

```
OceanRenderer（调度：LOD、时间、参数）
└─ Shape 输入（波形的来源，可替换）
   ├─ ShapeGerstner      少量大波，CPU 算，便宜
   ├─ ShapeFFT           GPU 频谱，真实但贵
   └─ ShapeGerstnerBatched
├─ LOD 网格（clipmap：近密远疏）
├─ 表面渲染（法线、泡沫、SSS、折射）
├─ 平面反射（内置，不是 SSR）
├─ 水下渲染（Underwater Renderer）
└─ 交互（船尾迹、浮力采样）
```

### 2.1 关键设计一：波形是"可替换的输入"

`Shape*` 组件决定波形，渲染层只消费"位移图 + 法线图"。

**这正是我们项目里 `IWaterSimulation` 在做的事** —— 我们方向对了，但 Crest 把它做成了"运行时切换 + 多个实现共存"，我们只有编译期切换。

### 2.2 关键设计二：LOD 用 clipmap，不用细分

Crest 不靠硬件 Tessellation 铺满整片海，而是**一块块同心网格**，近处密、远处疏，跟着相机走。

原因：
- 硬件细分在大面积上会浪费（远处看不出差别）
- clipmap 网格密度可控，性能可预测

**我们的问题**：现在是固定 128×128 的单一网格覆盖 200m。范围一大，密度就不够；范围一小，又浪费。这是应该照抄的第一件事。

### 2.3 关键设计三：平面反射是"自带"的

Crest 的反射不是 SSR，而是**独立的镜像相机 + RenderTexture**：

```
镜像相机（关于水平面反射）→ RT → 水面 shader 用屏幕坐标采样
```

优势：稳定、不闪烁、能看到屏幕外的东西。
代价：每帧多渲染一遍场景。

**这正好是你想要的"平面实时反射"。** 实现路径明确，不需要猜。

### 2.4 关键设计四：深度缓存（Ocean Depth Cache）

Crest 把海底地形渲染到一张"深度图"里，shader 用它算水深。

**我们已经在做同样的事**（`CoastTerrain.BuildHeightMap` → `_HeightMap`）。这一条我们是对的，只是 Crest 用的是真实渲染而非函数烘焙。

### 2.5 关键设计五：泡沫来自"流速 + 浪高"

Crest 的泡沫不是一个阈值：
- 浪尖处（高度接近峰值）→ 泡沫
- 流速差异大处（波形梯度大）→ 泡沫
- 再叠噪声与生命周期

**我们的问题**：只有深度差 + 简单噪声，所以看起来是"贴边白带"。

## 3. Tessendorf FFT 的工程要点

论文本身是数学，但工程上只有四条要记住：

1. **位移图与法线图各做一次逆 FFT**（法线不是从高度差分出来的，而是在频域乘 `i·k` 再变换）
2. **Choppiness（折叠）**：横向位移让浪尖变尖，超过阈值会自交，需要钳制
3. **频谱参数化**：Phillips 谱的 `L`（风区长度）直接决定"海有多碎"
4. **时间演化**：`h(k,t) = h₀(k)e^{iωt} + conj(h₀(-k))e^{-iωt}`，ω = √(gk)

**我们现在的做法**：用频谱采样出 16 个波再叠加。
这是"逆 FFT 在 16 个采样点的逐点求值" —— 数学等价于只保留 16 个频点。
代价是带宽不足（细节少），收益是零 GPU 开销。

**结论**：要继续提升真实感，迟早要上 GPU FFT（Crest 的 `ShapeFFT` 就是范本），但不是现在。

## 4. SIGGRAPH 分享里的工程结论

两场分享反复强调的几点，和我们的现状对照：

| 结论 | 我们的现状 |
|---|---|
| 光靠几何做不出细碎水面，法线贴图是主力 | ✅ 已理解并实施 |
| 远处必须降低法线强度、提高粗糙度，否则走样 | ✅ 已实施（距离衰减） |
| 水面要有"次表面散射"才会透亮 | ⚠️ 只有简单的 tip/body 散射项 |
| 泡沫要有时空变化，不能是静态遮罩 | ❌ 目前是静态阈值 + 滚动噪声 |
| 水下效果需要独立一套渲染（雾、折射、焦散） | ❌ 完全没做 |
| LOD 决定了大范围可玩性 | ❌ 单块网格 |

## 5. MelodyRenderPipeline 能看什么

它是一个自定义 SRP 管线（非 URP/HDRP）。对我们最有价值的不是水体代码，而是：

- **怎么在管线层插入一个"水面 pass"**，而不是靠材质硬凑
- **RT 的管理方式**（反射 RT、深度 RT 的分配与复用）

我们目前是"HDRP 里塞一个 SRPDefaultUnlit 的自包含 shader" —— 能用，但没有管线层支持，
所以反射、水下、后处理都得自己手搓。

**如果要把水做到 Crest 那个级别，最终要么接 HDRP 自带的水系统，要么自己写一个轻量 SRP。**

## 6. 对我们项目的六条可执行结论

按"投入产出比"排序：

| # | 做什么 | 依据 | 工作量 |
|---|---|---|---|
| 1 | **平面反射**（镜像相机 + RT + 屏幕投影采样） | Crest 自带 | 2–3 天 |
| 2 | **LOD clipmap 网格**替换固定网格 | Crest | 2 天 |
| 3 | 泡沫改成"浪高 + 梯度 + 生命周期" | Crest / SIGGRAPH | 1–2 天 |
| 4 | 次表面散射做完整（视角相关） | SIGGRAPH | 1 天 |
| 5 | 水下渲染（雾 + 折射 + 焦散） | Crest Underwater | 3–5 天 |
| 6 | GPU FFT（`ShapeFFT` 级别） | Tessendorf | 1 周+ |

**第 1 项是你已经点名的**，且实现路径最清晰（不需要 FFT、不需要改管线）。

## 7. 差距总表

| 能力 | Crest | 我们 |
|---|---|---|
| 波形 | Gerstner + GPU FFT 可切 | 频谱采样的 16 波（CPU） |
| LOD | clipmap 多级 | 单块 128×128 |
| 法线 | 位移图求导 + 细节贴图 | ✅ 两层滚动 + 距离衰减 |
| 反射 | 平面反射（自带） | 环境 cubemap 近似 |
| 泡沫 | 浪高 + 梯度 + 生命周期 | 深度差 + 噪声 |
| 水下 | 完整（雾/折射/焦散） | 无 |
| 交互 | 船尾迹、浮力 | 浮力有，尾迹无 |
| 管线集成 | 深度集成 | 自包含 shader，无管线支持 |

---

## 8. 一句话总结

**Crest 值得抄的是架构（LOD、可替换波形、平面反射、深度缓存），不是代码。**

我们已经独立走到了正确的骨架（证据接口、可替换模拟、深度图、距离衰减），
接下来的差距集中在**平面反射**和**LOD**这两件工程问题，而不是算法问题。
