# 一、目标美术风格（用户指定）

用户提供的参考图 + 视频画面共同指向**风格化俯视森林**：

| 元素 | 做法 |
|---|---|
| 树 | 低多边形树干 + **块状/团簇状树冠**，不是真实叶片 |
| 草 | **色块拼接**：多个绿色调分块，边缘不规则 |
| 土路 | 米色/棕色，**边缘柔和过渡**，不是硬边 |
| 石头 | 低多边形，灰蓝/紫灰，有简单高光边 |
| 花 | 小十字/星形，黄白＋紫，散落点缀 |
| 光照 | 柔和阴影，大量环境光，对比度低 |
| 调色板 | **有限且低饱和**：绿（多档）、米、灰紫、黄白 |
| 体积光 | **竖直光柱**，从树冠缝隙漏下，柔和边缘 |

**关键判断**：这是"**视觉一致性优先于真实感**"的路线（参考 Dungeons of Hinterberg 的做法），**单人可做**。

# 二、视频揭示的核心技术：面片叠加式体积光

## 视频字幕原文

> **"绘制平行于光线且垂直于视角的面片，并进行叠加"**
> **"进行调参柔和"**

## 这是什么

不是光线步进（raymarch），而是：

```
1. 沿光线方向生成若干张面片（quad）
2. 每张面片朝向相机（billboard），但**沿光线轴对齐**
3. 面片上画"光柱的截面"（可以用噪声 + 屏幕空间遮罩）
4. **加性叠加**所有面片 → 形成体积感
```

## 为什么这招对我们重要

我们现在的 GodRay 是**屏幕空间 radial**（32 步 × 3 tap），文档里记录的问题：

- 有台阶/拉伸
- 半分辨率做不出来
- ray march 累积不稳定

而**面片叠加法**：

| 优势 | 说明 |
|---|---|
| **不依赖后处理链** | 直接作为几何体画，不需要半分辨率 RT |
| 可以做出**真实遮挡** | 面片被树挡住就是硬遮挡，不需要深度重建 |
| 成本可控 | 面片数量是主要成本，可以按距离剔除 |
| 风格化友好 | 面片化的光柱天然适合风格化美术 |

**这正好绕开了我们自建 SRP 最薄弱的一环（后处理/半分辨率链路）。**

# 三、我们的差距

## 美术层

| 项 | 我们 | 参考 | 性质 |
|---|---|---|---|
| 树 | 无（Props 里零散） | 低多边形团簇树冠 | 缺内容 |
| 草 | 无 | 色块拼接 | 缺内容 |
| 地表 | 单色 | 多色块 + 柔和过渡 | 缺功能 |
| 花/小物 | 无 | 散落点缀 | 缺内容 |
| 调色板 | 无统一规划 | 有限低饱和 | 缺规范 |

## 技术层

| 项 | 我们 | 参考 | 性质 |
|---|---|---|---|
| 体积光 | 屏幕空间 radial（有缺陷） | 面片叠加 | 架构优（可替换） |
| 云 | 2D 天空盒 + 半成品体积云 | 视频里云很淡 | 可简 |
| 阴影 | 自建级联 + 月亮 | 柔和单光源 | 可简 |

# 四、结论：美术方向应定为"风格化"

理由：

1. **用户指定的参考就是风格化**
2. **单人 + 一个协作者**做不了写实的资产量
3. 风格化对**技术缺陷更宽容**（低对比、柔和阴影能掩盖阴影/水的瑕疵）
4. 风格化让**程序化生成**（我们的地形/植被）看起来是"设计"而不是"没做完"

## 具体技术调整（相比现在）

| 现在 | 应改为 |
|---|---|
| PBR 写实着色（FenglingLit 有金属度/粗糙度） | **简化**：漫反射为主 + 少量高光，降低对比 |
| 真实日月天文 | **保留**（这是特色，风格化也需要昼夜） |
| 写实水面（反射/折射） | **简化**：纯色 + 波纹法线 + 菲涅尔，弱化反射 |
| 屏幕空间 GodRay | **面片叠加光柱** |
| 体积云 | **降级**：风格化用简单图层云即可，省性能 |
