# 一、用户的 4 条观察 vs 我们的现状

| # | 视频特征 | 用户判断 | 我们的状态 | 差距性质 |
|---|---|---|---|---|
| **1** | 局部不规则的自然形态，**伞状半圆**，边缘起伏有破损，向画面外延伸 | ✅ 正确 | 🟡 **竖蛋形**（5.88×7.51，高>宽） | **形状参数错** |
| **2** | **强烈像素马赛克感**，粗犷方形像素块，复古游戏颗粒感 | ✅ **这是关键** | ❌ **完全没有** | **缺功能（低分辨率渲染）** |
| **3** | **像素化明暗对比**，深浅绿方块直接拼接，**无平滑过渡** | ✅ 正确 | ❌ **平滑渐变** | **缺功能（色阶量化）** |
| **4** | 树干体积和直立可见，**树枝隐没在树冠中** | ✅ 正确 | 🟡 树干只露一点 | **参数问题** |

**结论：差距 1 和 4 是参数问题（好改），差距 2 和 3 是缺失的渲染技术（要新增 Pass）。**

## 2.2 四个必须同时满足的技术条件

```
① 低分辨率渲染    → 有的"方块感"来源
② 色阶量化        → "深浅绿方块直接拼接，无平滑过渡"的来源  ← 我们缺这个
③ 最近邻放大      → 保持方块边缘锐利
④ 相机像素吸附    → 防抖动（可选，但 t3ssel8r 有）
```

**我们目前只做了 ①③，缺 ②④。**

# 三、逐条分析

## 差距 1：伞状半圆 vs 竖蛋形

### 数据
| | 视频 | 工程网格 | 我们 |
|---|---|---|---|
| 宽高比 | **约 1.4~1.5（宽>高）** | **0.78（高>宽）** | 0.80 |

### 原因
工程自带的 `树叶` 网格是**竖立的蛋形**（包围盒 5.88 × 7.51 × 6.03），
而视频里的树是**伞状/半圆**（宽 > 高）。

**这不是参数问题，是形状网格的方向不对。**

### 解法
```
对工程 树叶 网格做变形：
  Y 轴压扁到 0.65~0.75
  XZ 轴放大到 1.15~1.25
  → 宽高比从 0.78 变成 1.35~1.45
```
这属于 `ShapeVariants.MakeVariant` 的 `scaleMin/scaleMax` 的**非均匀缩放**能力，
但要改成**只按轴分别指定**（当前是各轴独立随机）。

### 视频的另一个特征：「边缘起伏有破损」
由**叶片精灵在轮廓外探出**产生 —— 我们的 DrawLeaf 已经有（`LeafOffset` 0.356 让叶子沿法线外推）。
**低分辨率量化后这些探出的叶子会变成方块的"破边"。**

---

## 差距 2：像素马赛克感（❌ 完全没有）

### 原因
我们直接渲染到 512×512（或 1920×1080）→ **每个像素都是独立计算的** → 没有方块。

### 解法（已验证可行）
```csharp
// 渲染到 640×360，filterMode = Point
var rt = new RenderTexture(640, 360, 24, RenderTextureFormat.ARGB32);
rt.filterMode = FilterMode.Point;
cam.targetTexture = rt;
cam.Render();
// 然后放大 3× 到 1920×1080（最近邻）
```

**我们已经在 `LowResTree.cs` / `CopyProjectScene.cs` 里实现过，效果验证有效**（见 `Docs/images/t3ss/copy_project/lowres_tree.png`）。

**但注意**：低分辨率必须配合"树占画面比例正确" —— 640×360 里树占 300px 高时，每个叶子才 1~2 像素。

---

## 差距 3：像素化明暗对比，无平滑过渡（❌ 我们是平滑渐变）

### 这是最容易被忽略的一条！

**用户说「深浅绿方块直接拼接，没有平滑过渡」—— 这不只是分辨率低，还因为【色阶被量化了】。**

### 原理
```
连续渐变：  L = 100, 103, 106, 109, 112 ...  ← 肉眼觉得平滑
量化到 4 级：L = 100, 100, 100, 110, 110 ...  ← 明显色块
```

**低分辨率 + 最近邻放大只产生"空间上的方块"，但每个方块内部仍是渐变色。**
**要产生"深浅绿方块"，必须把颜色也量化成有限的几级。**

### 解法：加一个 Quantization Pass

```hlsl
// 后处理 shader
float3 QuantizeColor(float3 c, float steps)
{
    return floor(c * steps + 0.5) / steps;
}

half4 frag(Varyings IN) : SV_Target
{
    half3 c = SAMPLE_TEXTURE2D(_MainTex, sampler_MainTex, IN.uv).rgb;
    c = QuantizeColor(c, _Steps);   // _Steps = 4~8
    return half4(c, 1);
}
```

**效果**：树上只有 4~8 种绿色 → "深浅绿方块直接拼接"

### 实现位置
在 `NoramlLineRenderPassFeature` 里加**第三个 Pass**，或者单独做一个 `PixelArtPostProcessFeature`：
```
Downsample(640×360) → 渲染 → 描边 → ★量化 → 放大(最近邻)
```

## 差距 4：树干体积和直立可见

### 现状
- 树干网格（24756 顶点）渲染了
- 但被树冠挡住，只露出底部一点

### 视频
- 树干**明显可见**，占全树高约 30%
- 树枝（树干上部）**隐没在树冠里**

### 原因
工程的树冠是竖蛋形，把树干大部分包住了。
**如果按差距 1 把树冠改成伞状（Y 压扁），树干会自然露出更多。**

### 解法
```
① 树冠 Y 压扁（差距1的解法）→ 树干自然露出
② 树干上移 / 树冠上移，让树干占 30% 高度
③ 树干颜色保持深紫褐 (0.29, 0.21, 0.25)
```

# 四、完整技术方案

## 4.1 渲染管线（5 Pass）

```
Scene (全分辨率)
   ↓
① Downsample → 640×360（点采样）
   ↓
② NormalLine Outline（内部res，1px 描边）
   ↓
③ ★ Quantization（色阶量化，4~8 级）        ← 新增
   ↓
④ Nearest Upscale → 1920×1080
   ↓
输出
```

## 4.2 树的参数（保持 e2a6e4f）

```
LeafDenesity      0.443
LeafSize          1.449
LeafOffset        0.356
LightOffset       0.396
LightOffsetDenesity  未设置（默认 0）
_LightOffsetScale 0.396
_SunDir           (0.35, 0.85, 0.40)
渐变              Dark(0.333,0.384,0.299) → Light(0.686,0.790,0.660)
环境光            (0.40, 0.46, 0.44)
光强              1.4, 软阴影
相机              frameSize = max(extents) × 1.25
地面              scale (3,1,3)
```

**⚠️ 这些值在 `e2a6e4f` 已验证正确，不允许同时改多个。**

## 4.3 形状修改（差距 1）

```
对工程 树叶 网格做非均匀缩放：
  scale = (1.20, 0.68, 1.20)   ← 宽高比 0.78 → 1.38
  → 伞状/半圆
```

## 4.4 执行顺序（重要）

1. **先做差距 2+3**（低分辨率 + 量化）→ 这是"像素风"的核心
2. **再做差距 1**（形状压扁）
3. **最后做差距 4**（树干比例）

**每次只改一项，改完对比，通过才继续。**

# 六、结论

**差距 2 和 3 是同一个问题的两面：**
- 差距 2（方形像素块）= **低分辨率 + 最近邻放大**
- 差距 3（深浅绿方块）= **色阶量化**

**我们只做了低分辨率，没做量化 → 所以只有"方块"没有"色块"。**

**补齐量化 Pass + 形状压扁 + 树干比例，就能达到视频效果。**
