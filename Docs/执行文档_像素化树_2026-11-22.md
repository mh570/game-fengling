# 零、先回答核心质疑

## 0.1 「这绝对不是调参数这么简单」—— 完全正确

**证据：工程里根本没有像素化和色阶量化的实现。**

我把 `C:\baidunetdiskdownload` 全部资产清点了一遍：

| 类别 | 数量 | 内容 |
|---|---|---|
| **相关 C# 脚本** | **2 个** | `DrawLeaf.cs`（5267 字节）、`NoramlLineRenderPassFeature.cs`（4121 字节） |
| 无关脚本 | 5 个 | PrefabPainter 工具 |
| **Shader** | **5 个** | `Grass` / `Leaf` / `NormalLIne` / `NormalTex` / `Unlit`（全是 ShaderGraph） |
| 第三方包 | 1 个 | `Cyanilux/URP_ShaderGraphCustomLighting`（Toon 分阶，**叶子没用**） |
| 材质 | 15 个相关 | 6 个树相关 + 5 个草 + NormalLine 2 个 |
| 场景 | 1 个 | `SampleScene.unity` **58 MB**（2297 个草实例，**没有树**） |

**结论：工程只有「树」和「草」的实现，没有「像素化」和「色阶量化」。**

## 0.2 视频和工程的关系

```
视频 = t3ssel8r 本人的作品（他的渲染器有像素化管线）
工程 = 中文教程作者对这个视频的「复刻」
        ↓
复刻了：树模型 + DrawLeaf + Leaf shader + Unlit + 法线描边 + 后期
没复刻：像素化管线、色阶量化
```

**所以：树的部分可以「抄工程」，像素化的部分必须「自己做」。**

## 0.3 方案可行性论证

# 一、完整逻辑链（已验证）

## 1.1 工程的树渲染逻辑

```
model.fbx
├── 树叶 网格（3019 顶点 = 5 个球堆叠，每球独立法线）
│     ↓ 只当顶点源，渲染成纯色（Unlit.shadergraph）
├── 树干 网格（24756 顶点）
│     ↓ 纯色（同一个 Unlit.shadergraph）
└── DrawLeaf.cs
      ↓ 遍历 树叶 网格的 3019 个顶点
      ↓ 44.3% 的顶点上放一片叶子（LeafSize 1.449）
      ↓ 叶子用 Leaf.shadergraph 着色
```

## 1.2 叶片着色逻辑（`Leaf.shadergraph` 反编译结果）

```
节点链：PositionNode → 球面法线
         ↓
    DotProductNode(N · SUN_DIR)
         ↓
    RemapNode(-1..1 → 0..1)
         ↓
    ★ SampleGradient（6 个关键帧）
         ↓
    × _Color（(0.494, 0.937, 0.384) 绿色）
         ↓
    × 树叶.png 的 alpha
```

**渐变实测数据（从 shadergraph JSON 提取）**：
```
m_NumColorKeys = 6
key0: RGB(0.283, 0.298, 0.358) @ 0.203
key1: RGB(0.402, 0.424, 0.481) @ 0.406
key2: RGB(0.440, 0.466, 0.538) @ 0.624
key3: RGB(0.603, 0.645, 0.764) @ 0.832
key4: RGB(0.678, 0.727, 0.858) @ 0.965
key5: RGB(1.000, 1.000, 1.000) @ 1.000
```

**⚠️ 关键：这是 6 帧平滑渐变，不是色阶。**
**所以「深浅绿方块直接拼接」的效果，工程里做不出来 —— 必须加量化。**

## 1.3 后期处理（`SampleSceneProfile.asset`）

```
Tonemapping:  Neutral  (m_Value: 1)
Bloom:        intensity 1
Vignette:     intensity 0.25, smoothness 0.4
```

**⚠️ 我曾在 e2a6e4f 基础上加了这三项，导致渐变被压缩 31%（实测 L 159→92 变成 133→90）。**
**树的验证渲染要关掉它们。**

## 1.4 描边（`NoramlLineRenderPassFeature.cs`）

```
Pass1 DrawNormalTexPass:
  用 NormalTex.mat（ShaderTagId "DepthOnly"）把场景法线渲染到 _NormalTex
Pass2 DrawNoramlLinePass:
  用 NormalLien.mat 对法线图做方向性对比 → 描边
  passEvent: AfterRenderingPrePasses (150)
```

**Unity 6 适配版已写好（`NoramlLineRenderPassFeature_Unity6.cs`），编译通过。**

# 二、差距的「逻辑定性」

| # | 视频特征 | 差距性质 | 根因 |
|---|---|---|---|
| **1** | 伞状半圆、边缘破损 | **参数错** | 工程网格宽高比 0.78（竖蛋），视频是 1.4~1.5（伞状） |
| **2** | **强烈像素马赛克** | **缺功能** | 工程没有低分辨率渲染 |
| **3** | **深浅绿方块、无平滑过渡** | **缺功能** | 工程没有色阶量化（渐变是 6 帧平滑的） |
| **4** | 树干可见、树枝隐没 | **参数错** | 树冠把树干包住了 |

**1、4 是参数问题（好改）；2、3 是缺失的渲染环节（要新增 Pass）。**

# 三、执行计划（严格按序，一次只改一项）

## 阶段 A：确认基准可复现（已完成的验证）

| 步骤 | 内容 | 验证标准 |
|---|---|---|
| A1 | 用 `git checkout e2a6e4f -- t3ss/ImportedTreeTest.cs` 恢复基准 | 编译通过 |
| A2 | 运行渲染 | 采样：冠上 L≈145~159，冠中 L≈107，冠下 L≈92 |
| A3 | 确认渐变存在 | 顶亮底暗，跨度 ≥ 50 |

**✅ 已完成（`Docs/images/t3ss/e2a6e4f_restored.png`）**

## 阶段 B：加像素化（差距 2）

| 步骤 | 内容 | 验证标准 |
|---|---|---|
| B1 | 渲染分辨率 512×512 → **640×360**（`filterMode = Point`） | 输出尺寸正确 |
| B2 | 最近邻放大 3× → 1920×1080 | 出现明显方块 |
| B3 | 采样色块大小 | 每块 3×3 像素 |

**⚠️ 关键参数**：树在 640×360 里必须占 ~290px 高（对应视频里 300px），叶子才会变成 1~2px。

## 阶段 C：加色阶量化（差距 3）★ 最关键

| 步骤 | 内容 |
|---|---|
| C1 | 写 `Quantize.shader`：`floor(c*steps+0.5)/steps` |
| C2 | 做成 `ScriptableRendererFeature`（在 FinalBlit 之前） |
| C3 | steps 从 8 开始试，逐步降到 4 |
| C4 | 验证：树冠只出现 4~8 种绿色 |

**量化 shader**：
```hlsl
half4 frag(Varyings IN) : SV_Target
{
    half3 c = SAMPLE_TEXTURE2D(_MainTex, sampler_MainTex, IN.uv).rgb;
    c = floor(c * _Steps + 0.5) / _Steps;
    return half4(c, 1);
}
```

## 阶段 D：伞状树冠（差距 1）

| 步骤 | 内容 |
|---|---|
| D1 | 用 `ShapeVariants.SmoothVariant` 对工程网格做**非均匀缩放** |
| D2 | scale = (1.20, 0.68, 1.20)（宽高比 0.78 → 1.38） |
| D3 | 法线用逆转置矩阵修正 |

## 阶段 E：树干比例（差距 4）

| 步骤 | 内容 |
|---|---|
| E1 | 树冠压扁后，检查树干露出比例 |
| E2 | 目标：树干占全树高 25~30% |
| E3 | 必要时上移树冠或下移树干 |

## 阶段 F：描边（可选）

| 步骤 | 内容 |
|---|---|
| F1 | 调 `_Edge` 从 0.3 → 0.85（降低阈值） |
| F2 | 检查描边是否出现 |

# 四、每步的验证方法

## 4.1 必做的三项验证

| 验证 | 方法 |
|---|---|
| **编译 0 error** | `Unity.exe -batchmode -quit -projectPath <proj> -logFile <log>` |
| **渲染成功** | 检查 PNG 是否生成 + 尺寸正确 |
| **采样比对** | 采样树冠上/中/下的 RGB 和亮度 |

## 4.2 禁止事项

| 禁止 | 原因 |
|---|---|
| **一次改多个参数** | 本次教训：同时改 7 项，坏了分不清 |
| **用 `git show \| Set-Content` 导出文件** | 会吞掉换行 → 单行文件 → 编译错误 |
| **用 PowerShell `.Replace()` 改代码** | 找不到文本时**静默无操作** |
| **用 `>` 重定向写 shader** | 写成 UTF-16，Unity 读不了 |
| **改已确认正确的 `e2a6e4f` 参数** | 树的参数是对的 |

## 4.3 正确做法

| 场景 | 工具 |
|---|---|
| 改代码 | **`edit` / `write` 工具** |
| 导出 git 文件 | **`git checkout <commit> -- <file>`** |
| 找参数差异 | **逐项 `Select-String` 提取后对比** |

# 六、风险与备选方案

| 风险 | 概率 | 备选 |
|---|---|---|
| 量化后颜色太脏 | 中 | steps 调到 8~12 |
| 低分辨率后树太小 | 中 | 调 `frameSize` 让树占 80% 高度 |
| 描边不出现 | 中 | 手动调 `_Edge` 或改 `_Width` |
| 伞状变形后法线错 | 低 | 用逆转置矩阵（已验证） |
| **项目最终要在游戏里跑** | — | 这些 Pass 都要做成 URP RendererFeature |

# 八、结论

**方案可行，依据如下：**

1. **树的渲染逻辑已完全搞清**（`模型 + DrawLeaf + Leaf shader + Unlit + 描边`），参数已在 `e2a6e4f` 验证正确
2. **像素化方案有外部实证**（StackOverflow / Red Giraffe / bababuyyy 管线）
3. **色阶量化有明确数学形式**（`floor(c*steps+0.5)/steps`）
4. **描边 Pass 已适配到 Unity 6 并编译通过**

**缺的只有两个 Pass（像素化 + 量化）和两个参数调整（形状压扁 + 树干比例）。**

**这不是玄学调参，是补齐两个明确的渲染环节。**
