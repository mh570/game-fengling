# 一、外部经验（每阶段反闭门造车的依据）

| 来源 | 关键结论 | 对本项目的影响 |
|---|---|---|
| [Catlike Coding Custom SRP 7.0.0](https://catlikecoding.com/unity/custom-srp/7-0-0/) | Unity 6.5 起 `ImportBackbuffer` 必须传 `RenderTargetInfo`；renderer list culling 被移除；LPPV 废弃 | **自建 SRP 有明确的版本悬崖**，API 现代化不能无限拖 |

| [cinight/CustomSRP](https://github.com/cinight/CustomSRP) | 多个迷你 SRP，各演示一种能力，只用 SRP Core | 遇到具体问题时按需参考 |

# 四、阶段 P2：EnvironmentContext（1 天）

## 问题

`Fengling.Time` 和 `Fengling.Environment` **不引用任何模块**，数据无法直接推给渲染层，只能靠：

- `Shader.SetGlobalFloat(...)` 全局变量
- `FindFirstObjectByType<...>()` —— **36 处**

## 步骤

1. 定义 `EnvironmentState`（纯数据）：时间、日月方向/颜色/强度、月相、天气参数、曝光、雾
2. 定义 `EnvironmentContext`（单一持有者，注入式获取，不做静态单例）
3. `TimeOfDaySystem` / `WeatherSystem` 每帧写入 context
4. 渲染 / 水体 / 天空 / 阴影 从 context 读，**删除 Find**
5. 全局 shader 变量保留（shader 侧仍需要），但**只由 context 一个地方推送**

## 验收（自动）

- `FindFirstObjectByType` 从 36 处降到 **≤ 5 处**（剩余的是合法的编辑器工具）
- 探针场景：切换时间 → 下一帧采样值即变化（证明无执行顺序依赖）

## 验收（人工）

- 在 RpgLab 里手动切时段，画面同步

## 风险

- 改动面大（Time/Weather/Water/Rendering 四个模块）→ 分两步：先加 context 并行运行，再逐个切换消费方，最后删旧路径

# 五、阶段 P3：渲染 API 现代化（1.5 天）

## 问题

19 条警告，6 类废弃 API：

| API | 处数 |
|---|---|
| `ScriptableRenderContext.DrawRenderers` | 4 |
| `DrawSkybox` | 1 |
| `ShadowDrawingSettings.splitData` | 2 |
| `RenderPipeline.Render(ctx, Camera[])` | 1 |

## 为什么必须做

Unity 6.5 会**直接破坏**未迁移的自建 SRP（`ImportBackbuffer` 必须传 `RenderTargetInfo`）。这不是洁癖，是版本悬崖。

## 步骤

1. 先迁移 `DrawRenderers` → `CreateRendererList` + `CommandBuffer.DrawRendererList`
2. 再迁移 `DrawSkybox` → `CreateSkyboxRendererList`
3. `splitData` → `CullShadowCasters`
4. `RenderPipeline.Render(ctx, Camera[])` 换新重载
5. **不在本阶段做**完整的 RenderGraph 迁移（那是更大的工程，单独评估）

## 验收（自动）

- 编译警告数 **0**
- 探针对比：三块采样与 P0 基线一致（偏差 < 5）

## 风险

- RendererList 与 culling 的配合容易出错 → **每迁一处就跑一次探针**，不一次性全改

## 18.1 API 事实（试错得来，下次直接用）

### RenderGraph 命名空间

```csharp
using UnityEngine.Rendering.RenderGraphModule;   // 不是 UnityEngine.Rendering
```

### UnsafeGraphContext 不暴露 renderContext

`SetRenderFunc` 拿到的 `UnsafeGraphContext` 只有 `cmd`，没有 `renderContext`。
现有逻辑需要 `ScriptableRenderContext` 时，用**外层方法捕获的 `context`**（这是桥，转 raster 后会消失）。

### RendererList 的正确写法 ⚠️ 最容易踩

```csharp
// ❌ 不存在三参重载，会报 CS1501
context.CreateRendererList(culling, drawingSettings, filteringSettings);

// ✅ 先构造 RendererListParams，再传 ref
var prm = new RendererListParams(culling, opaqueSettings, opaqueFilter);
var list = context.CreateRendererList(ref prm);

var cmd = CommandBufferPool.Get("Fengling.OpaqueDraw");
cmd.DrawRendererList(list);
context.ExecuteCommandBuffer(cmd);
CommandBufferPool.Release(cmd);
```

`RendererListParams` 的构造函数**在引擎 dll 内**，SRP Core 包源码里没有，无法通过读源码确认。

### RenderGraph 调用顺序（来自 HDRP 实测代码）

```csharp
var cmd = CommandBufferPool.Get();
var parameters = new RenderGraphParameters
{
    executionId = camera.GetEntityId(),      // EntityId 类型
    currentFrameIndex = Time.frameCount,
    scriptableRenderContext = context,
    commandBuffer = cmd,
};
_renderGraph.BeginRecording(parameters);
using (var builder = _renderGraph.AddUnsafePass<PassData>("Name", out var data))
{
    builder.AllowPassCulling(false);
    builder.SetRenderFunc<PassData>((d, ctx) => { ... });
}
_renderGraph.EndRecordingAndExecute();
context.ExecuteCommandBuffer(cmd);
CommandBufferPool.Release(cmd);
```

### splitData 的替代（来自 HDRP `LightLoop.cs`，尚未实施）

```csharp
NativeArray<LightShadowCasterCullingInfo> perLight =
    new NativeArray<LightShadowCasterCullingInfo>(culling.visibleLights.Length, Allocator.TempJob);
NativeArray<ShadowSplitData> splitBuffer =
    new NativeArray<ShadowSplitData>(lightCount * maxSplits, Allocator.TempJob);

perLight[lightIndex] = new LightShadowCasterCullingInfo
{
    splitRange = new RangeInt(0, splitCount),   // 注意：是范围，不是单个
    projectionType = ShadowSplitData.ShadowCullingProjectionType.Orthographic,
    splitExclusionMask = 0,
};
splitBuffer[0] = split;   // 4 个级联全放进去

var infos = default(ShadowCastersCullingInfos);
infos.splitBuffer = splitBuffer;
infos.perLightInfos = perLight;
context.CullShadowCasters(culling, infos);

splitBuffer.Dispose();
perLight.Dispose();
```

**关键结构变化**：现在的代码是"每个级联切片单独建一次 renderer list"，新 API 要求"一次提交该光源的所有 split"。**改这个等于重写级联循环**，所以和它一起做。

## 15.1 强制规矩（P2 起生效）

> **任何"某某不正常"的结论，必须先在项目自带场景（`RpgLab`）里复现一次，才允许写进结论。**

具体做法：

1. 探针里复现 → 记录现象
2. **切到 RpgLab 再复现一次**
3. 两次一致 → 结论成立
4. 两次不一致 → 先查探针，不查项目

这条规矩同样适用于 P2（EnvironmentContext）和 P3（API 迁移）——它们动的是实时渲染路径，误判代价更大。
