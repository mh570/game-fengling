# 二、验证方法

## 2.1 探针设计

一个空场景，只有三样东西 + 一盏平行光：

| 对象 | 材质 | 目的 |
|---|---|---|
| 立方体 | 默认（内置 Standard） | 不透明对照 |
| Quad | `Sprites/Default`，绿色 75% alpha | 透明队列 |
| ParticleSystem | `Particles/Standard Unlit`，红色 | ParticleSystemRenderer |

渲染一帧 → 存 PNG → 同时打印三块区域的平均 RGB。不用肉眼，用数字。

## 2.2 必须进 Play 模式

**编辑模式下 ParticleSystem 不参与相机渲染**，只在 Scene 视图预览里出现。第一版探针在编辑模式跑，得到的是假阴性。

## 2.3 探针自身踩的坑（记录以免重复）

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | 编辑模式测粒子 | 假阴性，粒子永远不出现 | 必须 Play 模式 |
| 2 | `-quit` + `-executeMethod` | 方法一返回就退出，Play 还没开始 | 去掉 `-quit`，由脚本调 `EditorApplication.Exit` |
| 3 | 进 Play 触发 domain reload | 静态字段与 update 订阅丢失，回调不再执行 | `SessionState` + `[InitializeOnLoadMethod] Reattach()` |
| 4 | `Camera.main` 依赖标签 | 自建相机拿不到，报"没有主相机" | 改用 `FindFirstObjectByType<Camera>()` |

**这四条都不是管线问题。** 项目里多个捕获脚本用的正是同一套模式（`cam.Render()` + update tick），所以它们的历史结论同样需要重新审视。

# 四、被推翻的旧结论

## 4.1 ❌「ParticleSystem 不可见 = 管线不支持」

**实测：144 个粒子正常渲染成红色，清晰可见。**

框架评估里"ParticleSystem 雨/雪不可见"的现象，**根因不是管线不支持**。可能的方向：

- 粒子对象本身没播放 / `playOnAwake` 关闭
- 粒子在相机子物体上，被 SRP 的裁剪或层级剔除
- 材质是内置 shader → 那应该是**洋红**而不是不可见

**结论：不能再用"管线不支持粒子"作为改用 Mesh 雨雪的理由。** Mesh 雨雪可以继续用（性能与观感理由可能依然成立），但**技术前提错了**。

## 4.2 ❌「透明队列不完整」

**实测：绿色半透明 Quad 正确混合背景。**

## 4.3 ❌「水面 shader 标了 HDRenderPipeline → 整片不渲染」

当前代码里 `FenglingWater.shader` **没有** `RenderPipeline` 标签；Pass 的 `LightMode = SRPDefaultUnlit`，而管线的透明队列正是用 `SRPDefaultUnlit` 绘制。

## 4.4 ❌「QualitySettings 三档绑着 HDRP 资产」

三档 `customRenderPipeline` 全部为 `null`（`fileID: 0`），都回落到 GraphicsSettings 的自建管线。

# 五、真正的问题（本次实测新发现）

## 5.1 🔴 内置 shader 的对象会显示洋红

立方体用的默认材质绑的是内置 `Standard` shader，在自建 SRP 下渲染成**洋红错误材质**。

**影响面**：任何没有走材质转换的对象都会洋红。项目里存在 `MaterialConverter` / `LitMaterialProvider`，说明这个问题被处理过，但**没有强制机制**——新加的对象很容易漏。

建议：加一个启动时或构建前的检查，扫描场景里材质 shader 不属于 `Fengling/*` 的 Renderer。

## 5.2 🟡 废弃的 SRP API（19 条编译警告）

| 废弃 API | 处数 | 官方替代 |
|---|---|---|
| `RenderPipeline.Render(ctx, Camera[])` | 1 | 新重载 |
| `ShadowDrawingSettings.splitData` | 2 | `CullShadowCasters` |
| `ScriptableRenderContext.DrawRenderers` | 4 | **RendererList API** |
| `ScriptableRenderContext.DrawSkybox` | 1 | `CreateSkyboxRendererList` |

现在能用，但这是唯一会随 Unity 升级失效的部分。

## 5.3 🟡 HDRP 残留

- `Packages/manifest.json` 仍引用 `com.unity.render-pipelines.high-definition 17.3.0`
- `Assets/Settings` 有 3 个 HDRP 管线资产（各 ~16 KB）+ 8 MB `WaterLabSky.asset`
- **已无任何档位引用它们**，属于纯残余

## 5.4 🟡 环境系统靠 Find 耦合

`FindFirstObjectByType` 全项目 **36 处**；`EnvironmentContext` 不存在。

# 六、修正后的判断

| 原判断 | 修正 |
|---|---|
| 管线缺透明/粒子路径 | **不缺**，实测都能渲染 |
| 需要补 Pass 收口才能继续 | 仍建议做 Pass 显式化，但**不是**因为"画不出来" |
| 半分辨率 GodRay 不可用 | 未验证，但**不能再归因于"管线不支持 RT"** |
| 框架方向对、缺架构层 | ✅ 仍然成立 |

**真正该做的顺序（修正后）**：

```
1. 内置 shader → 洋红的强制检查（新增对象不再漏）
2. EnvironmentContext（消除 36 处 Find）
3. DrawRenderers → RendererList（唯一会失效的部分）
4. 清 HDRP 残留
5. Pass 显式化（工程性改善，不是修 bug）
```
