# 代码走读笔记：水面链路

> 创建：2026-11-19 22:45 (+08:00)
> 维护：jixiangwu114
> 走读范围：`Assets/Game/Water`、`Assets/Game/Rendering`、`ProjectSettings` 的管线绑定

## 结论

1. **模块边界是编译期强制的**，不是口头约定：`Fengling.Player.asmdef` 只引用 `Water.Abstractions`，所以 Player 拿不到 `GerstnerWaterSimulation` 这类实现类型。删掉整个 `Water/` 目录，只会在场景里报"组件丢失"，不会有连锁编译错误。
2. **CPU 和 GPU 共用一组波，唯一通道是 `FillWaveData`**。渲染层不读 `settings.waves`，否则 Gerstner / Spectral 两套实现会出现两份数据源，玩家会浮在水面之上或之下。
3. **`amplitudeScale` 只乘一次**：在模拟器构造时固化进 `Amplitude`，渲染层固定 `_AmplitudeScale = 1`。这条不变量最容易在后续加功能时被破坏。
4. **时间只有一个推进点**（`WaterModule.WaterTime`），外部不许传时间进来，这样所有消费者看到的波形是同一帧的。
5. **当前最该先验证的是疑点 1**：新管线下水面可能整片不渲染。原因不在水模块，在 shader 的 SubShader 标签。

## 二、读代码时要盯住的五个不变量

| # | 不变量 | 位置 | 破坏后的症状 |
|---|---|---|---|
| 1 | 外部只认 `IWaterSurface` / `IWaterProvider` | `Abstractions/` 两个 asmdef | Player 能 `new` 出模拟器，边界名存实亡 |
| 2 | GPU 波参数只来自 `FillWaveData` | `WaterSurfaceRenderer.cs:195` | 改 Inspector 画面不动；或两份数据源对不上 |
| 3 | `amplitudeScale` 只乘一次 | `GerstnerWaterSimulation.cs:48` + `WaterSurfaceRenderer.cs:205` | 画面浪高是浮力的 2 倍 |
| 4 | 时间单点推进 | `WaterModule.cs:50` | 各消费者波形不同步，浮力与画面漂移 |
| 5 | 消费端允许"找不到水" | `WaterSurfaceRenderer.cs:83` 的 `FindFirstObjectByType` | 场景里两个 WaterModule 时，谁被选中不确定 |

## 三、疑点（按优先级，全部待实机验证）

### 1. 水面可能整块不渲染 —— SubShader 还标着 HDRenderPipeline

- `FenglingWater.shader:79`：`"RenderPipeline" = "HDRenderPipeline"`
- `FenglingPipelineAsset.cs:25`：`renderPipelineShaderTag => "FenglingForward"`
- `GraphicsSettings.asset:40`：`m_CustomRenderPipeline` 指向 `FenglingPipeline`
- 默认画质档是 `m_CurrentQuality: 0`（High Fidelity），它的 `customRenderPipeline` 为 null，于是回落到 GraphicsSettings 的自建管线

Unity 按 `renderPipelineShaderTag` 过滤 SubShader，标签不匹配的整段会被跳过。若成立，水面在新管线下不是"粉色"，而是**完全不出现**——比报错更难查。

验证方法：Play 后看水面是否存在；或临时把 Quality 切到 Balanced（那档仍绑 HDRP 资产）对比。

修法：删掉该行标签（对所有管线生效），或改成 `FenglingForward`。

### 2. 反射可能全黑 —— 用了内置管线全局量

`FenglingWater.shader:300/302`：`UNITY_SAMPLE_TEXCUBE(unity_SpecCube0, ...)`，兜底 `ShadeSH9`。

自建管线里既没有 `SetupReflectionProbes`，`DrawingSettings.perObjectData` 也是 `None`（`FenglingPipeline.cs:83`），这两个量很可能没被绑定。验证：关掉 `useReflectionCube` 看画面有无变化。

### 3. QualitySettings 仍在引用 HDRP 资产

| 档位 | customRenderPipeline |
|---|---|
| High Fidelity（当前） | `null` → 回落到自建管线 |
| Balanced | HDRP Balanced |
| Performant | HDRP Performant |

切档位等于**换渲染管线**，画面会整体变样，而且只有 HDRP 档下水面 shader 的标签才"正常"。这是迁移留下的地雷，比代码 bug 更隐蔽。

### 4. `FillWaveData` 的 `amplitudeScale` 是死参数

接口声明了它（`IWaterSimulation.cs:29`），两个实现都没用——因为构造时已经乘进 `Amplitude` 了。现在行为一致，但签名在骗人：谁照着签名传 2.0 期待放大，就得到静默的双重放大或不一致。

### 5. 风格化残留

`WaterSurfaceRenderer` 的 `stylized*` 五个字段，和 shader 里的 `_Stylized` / `_OpacityScale`，在「只保留写实风格」那次提交后就没有消费者了。属于可安全删除的死代码。

### 6. `UpdateTier()` 会改写 Inspector 值

`WaterSurfaceRenderer.cs:119` 起，`UpdateTier` 直接改 `useFoam` / `normalStrength` / `foamDistance` 等 public 字段。Play 一次，Inspector 里手调的设计值就被覆盖，停止后也不还原。
