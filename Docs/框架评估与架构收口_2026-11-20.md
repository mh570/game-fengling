# 一、结论摘要

**框架方向没有错，但架构不完整。**

已经证明可行的：

- 自定义 SRP
- 太阳 4 级统一 shadow atlas
- 月亮独立 2048 shadow map
- 真实日月位置 / 月相
- 天气、云、雨雪、水面
- 真机 720p 约 9–12ms CPU

现在的问题不是“选错引擎路线”，而是：

1. 自定义 SRP 缺少渲染特性层
2. 环境系统靠全局变量和 Find 耦合
3. 功能按需求增量堆叠，没有 Pass 设计
4. 内容生成管线缺少规范
5. QA / 性能验证不确定

这些问题还能靠临时开关和 QA 脚本维持，但继续加功能会重复踩坑。

**建议：不重写，先做一次框架收口（1–2 天），再继续视觉功能。**

# 三、当前问题与证据

## 1. 自定义 SRP 的透明 / 粒子 / 后处理路径不完整

### 表现

- ParticleSystem 雨/雪不可见
- 相机前 WeatherOverlay 不可见
- 半分辨率 GodRay 的 pass 3 纯红也不显示
- 最终绕成 Mesh 雨雪 + 全分辨率 radial

### 证据

- `TransparentProbeCapture`：透明 Quad 探针能显示
- `WeatherOverlay` / ParticleSystem 不显示
- `FenglingGodRays.shader` 纯红输出仍不显示
- 半分辨率链路已回滚

### 判断

不是材质问题，是：

- 透明队列 / ParticleSystemRenderer 路径没接完整
- PostProcess 缺少显式 RT pass 抽象
- `_GodRayTex` / Blit pass 链路不可靠

**这是渲染框架缺功能，不是美术问题。**

---

## 2. 系统靠全局 Shader 变量和 Find 耦合

### 表现

- `Shader.SetGlobalFloat("_Fengling...")`
- `FindFirstObjectByType<TimeOfDaySystem>()`
- `FindFirstObjectByType<WeatherSystem>()`
- 场景手动接引用

### 已出现的 bug

- QA 先 `SetTime` 再改天气 → `ApplySky` 没重跑
- 水面设置颜色后立刻 `cam.Render()` → WaterSurfaceRenderer 还没 Update
- Preset 场景 TimeOfDay/Weather 引用容易断
- 夜间 QA `enabled=0` 是渲染还没发生，不是逻辑错

### 判断

缺少一个 `EnvironmentContext` / `EnvironmentState` 单一入口。

---

## 3. 功能增量堆叠，没有 Pass 设计

当前管线同时存在：

- 太阳 atlas
- 月亮独立 map
- 体积雾 ray march
- radial GodRay
- 云影
- 水面反射
- Bloom / ACES
- 透明队列

但没有明确：

- Pass 顺序
- 哪些半分辨率
- 哪些按天气启用
- 哪些可以共存
- 输入/输出 RT

### 后果

- ray march 和 radial 两套 GodRay 并存
- 高云量/强雨靠“关效果”保性能
- 半分辨率 GodRay 修不通
- 透明/粒子路径绕开

**不是不能做，而是没有“渲染特性层”。**

---

## 4. Preset / 内容管线缺少规范

### 已发现的问题

- Rock 用 `PrimitiveType.Sphere` 生成，俯视是灰球
- Waterfall `foamStrength=2.4` 超出 shader 范围，白掉
- 沙地材质属性写成 `_Color`，实际是 `_BaseColor`
- 12:00 水面偏浅
- Fish/Plant 造型异常
- 6/18/0 在 11 月全是夜间

### 判断

内容生成管线没有：

- 资产规范
- 参数范围检查
- 材质属性检查
- 自动 QA

---

## 5. QA / 性能验证不确定

### 表现

- Editor 脚本 + Play Mode + SessionState
- 等固定秒数
- 手动 `cam.Render()`
- Unity 实例锁 / 编译卡住
- GPU FrameTiming 返回 0
- Preset 没逐个跑真机

### 判断

缺少确定性 QA / 性能 harness。

# 四、框架到底有没有问题

| 判断 | 结论 |
|---|---|
| 自定义 SRP 能不能做 | 能，已证明 |
| 双方向光阴影能不能做 | 能，月影已跑通 |
| 透明/粒子能不能支持 | 能，但现在没接完整 |
| GodRay 能不能做 | radial 能，ray march 未闭环 |
| 性能能不能达标 | 真机 9–12ms，基础可以 |
| 继续加功能会不会越来越痛 | 会 |

准确说：

**框架方向对，但缺架构层。**

不是“框架坏了”，是“框架还没抽象好，功能加得太快”。

# 五、目标架构

## 5.1 渲染 Pass 层

把“功能”变成显式 Pass：

```text
1. Sun Shadow Atlas
2. Moon Shadow Map
3. Sky
4. Opaque
5. Transparent
6. Water
7. PostProcess
   7.1 Volumetric / GodRay（半分辨率可选）
   7.2 Bloom
   7.3 Composite / ACES
```

每个 Pass 明确：

- 输入 RT
- 输出 RT
- 分辨率
- 是否按天气启用
- 是否可半分辨率

### 需要补的能力

- 透明队列 / ParticleSystemRenderer 正式支持
- 后处理显式 RT 链
- 半分辨率 pass + 上采样
- Pass 级开关 / 质量档

### 验收

- 一个 ParticleSystem 能显示
- 相机前透明 Quad 能显示
- 半分辨率纯色 Pass 能显示
- 半分辨率 GodRay 能显示

---

## 5.2 EnvironmentContext

新增一个环境状态中心：

```text
EnvironmentContext
  - TimeOfDay
  - SunDirection / SunColor / SunIntensity
  - MoonDirection / MoonColor / MoonPhase
  - Weather (cloud/haze/fog/rain/snow/wind)
  - Exposure / Fog
  - Shadow strength / moon strength
```

由它统一推给：

- Sky
- Water
- Lit
- Shadows
- PostProcess

场景只接一个入口。

### 要移除的

- 到处 `FindFirstObjectByType`
- 场景手动引用 Time/Weather
- QA 依赖执行顺序

### 验收

- 任意场景 Boot 后，环境状态一致
- 设置时间/天气后下一帧所有系统同步
- QA 不再需要“等 8 秒”

---

## 5.3 QA / 性能 Harness

需要确定性流程：

```text
固定场景
  → 固定时间/天气
  → 等 1 帧
  → 截图
  → 输出对比图
  → 自动跑六套 Preset
  → 自动构建 player
  → CPU/GPU CSV
```

### 验收

- 六套 Preset 一键出 6/12/18/0
- 真机 CPU/GPU 都有数据
- 失败自动标红

---

## 5.4 内容规范

- Rock / Fish / Plant 资产规范
- Waterfall 参数范围
- Preset 调色表
- 材质属性检查（`_BaseColor` vs `_Color`）
- 场景内容自动检查

# 六、收口路线

## P0：渲染 Pass 收口

1. 明确 Pass 顺序
2. 补透明/粒子 Renderer 路径
3. 后处理显式 RT 链
4. 半分辨率 GodRay 独立 Pass

预计：1 天  
验收：粒子、透明 Quad、半分辨率纯色、半分辨率 GodRay 都能显示

## P0：EnvironmentContext

1. 一个入口管理时间/天气/日月
2. 场景不再 Find
3. QA 不再依赖执行顺序

预计：0.5–1 天  
验收：设置后下一帧全系统同步

## P1：GodRay 单一化

二选一：

- 保留 radial，冻结 ray march
- 或修 ray march，删除 radial

不要两套都留。

预计：0.5 天  
验收：只有一条可交付路径

## P1：QA Harness

1. 固定时间/天气
2. 等帧
3. 自动截图
4. 六套 Preset
5. 真机 CPU/GPU CSV

预计：1 天  
验收：六套 Preset + 真机数据可重复

## P2：内容规范

1. Rock/Fish/Plant 资产规范
2. Waterfall 参数范围
3. Preset 调色表
4. 材质属性检查

预计：1 天  
验收：Preset 不再出现球体 Rock / 白掉 / 属性写错

# 七、不建议做的事

已证明可行的部分：

- 自定义 SRP
- 太阳 atlas
- 月亮 map
- 天文时间

在 Pass / EnvironmentContext / QA 收口前继续加：

- 水面月光
- 太阳细节
- 更多天气
- 更多 Preset
- 粒子特效

会重复现在的坑。

# 八、判断标准

## 如果只是短期 Demo

可以接受现状，优先：

1. Preset 美术
2. GPU 数据
3. 最终打包

## 如果项目还要长期做

现在就是最值得停下来收口架构的时点。

建议顺序：

```text
渲染 Pass 收口
  → EnvironmentContext
  → GodRay 单一化
  → QA Harness
  → 内容规范
  → 再继续视觉功能
```
