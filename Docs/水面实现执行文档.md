## 3. 阶段 1：海岸地形 ✅ 已完成

> 2026-11-18 完成：`Assets/Game/Environment/Terrain/CoastTerrain.cs`
> 程序化 mesh，128×128 = 16,641 顶点 / 32,768 三角形，高度函数 `SampleHeight(x,z)`。
> 场景构建器已改为使用它（原 30m 小岛 plane 已移除）。

### 目标

有一块**能看见海底缓坡**的地形，从沙滩到 5 米深，供泡沫和深度色使用。

### 参考

- Unity Terrain（内置）——最省事，但 HDRP 下要额外配置
- 或者手搓 mesh：一条 200×200 的网格，用高度函数 `h = -clamp(distanceFromShore, 0, 5)`

### 步骤

1. 新建 `Assets/Game/Environment/Terrain/`
2. 用高度函数生成 mesh（沙滩 → 缓坡 → 深海），不要用 Unity Terrain（对我们的需求太重）
3. 材质用 HDRP/Lit，给一张沙滩色 + 水下沙色
4. 打开 **Depth Texture**（HDRP 默认已开，`Project Settings → HDRP Global Settings → Rendering` 确认）

### 产出

```
Assets/Game/Environment/Terrain/
├─ TerrainGenerator.cs     程序化生成 mesh
├─ Sand.mat
└─ TerrainSettings.asset
```

### 验收

- [ ] 走一圈能看到沙滩、浅水、深水三段的颜色差异
- [ ] 地形 mesh 的面数 < 20k
- [ ] 水面和地形的交界处没有穿插

### 回滚

删掉 `Environment/Terrain/`，场景里的地形物体删掉即可。

## 4. 阶段 2：水面 Shader v1

### 目标

把线框换成真水面：**两层法线滚动 + GGX 高光 + 菲涅尔 + 深度混色**。

### 参考（按抄的顺序）

1. `flamacore/UnityHDRPSimpleWater` 抄**结构**（怎么在 HDRP 里接 ShaderGraph / 怎么写 HLSL 的 pass）
2. `MatrixRex/Uber-Stylized-Water` 抄**参数组织**（哪些参数该暴露、怎么分组）
3. 我们自己的《水面复刻手册》第 3、4 章抄**数值**

### 关键决策：用 HLSL 手写，不用 Shader Graph

原因：这台机器 2 核，每次改 Shader Graph 都要重编译 HDRP 变体，动辄 2–5 分钟。
HLSL 文本 shader 改一行立刻生效，迭代速度快 10 倍。

**只有在需要可视化调试时才开 Shader Graph。**

### 步骤

1. 新建 `Assets/Game/Water/Shaders/WaterSurface.shader`（HDRP Lit 的简化版）
2. 需要的输入：
   - 两层法线贴图（tiling 8 / 24，速度 0.02 / 0.034）
   - 太阳方向（HDRP 的 `_DirectionalLightDirection`）
   - 深度（`_CameraDepthTexture`）
   - 反射探针（`_EnvRefl`）
3. 顶点位移：**必须和 CPU 的 Gerstner 用同一组参数**（同一个 constant buffer）
4. 片元：法线混合（whiteout）→ GGX → 菲涅尔 → 深度混色

### 与 CPU 对齐（最容易出错的地方）

CPU 的 `GerstnerWaterSimulation` 和 GPU 的 vertex shader 必须用**完全相同**的波参数，
否则玩家看到的浮力和实际画面会错位（人浮在水面之上/之下）。

做法：把 `WaterSettings` 的波参数每帧塞进一个 `MaterialPropertyBlock` 或全局 shader 变量。

### 产出

```
Assets/Game/Water/Shaders/
├─ WaterSurface.shader
├─ WaterCommon.hlsl        波函数（CPU/GPU 共用逻辑）
└─ WaterSurface.mat
```

### 验收

- [ ] 水面有高光，随着相机转动在闪
- [ ] 近距离能看到细碎波纹，远处不闪
- [ ] 玩家站在水里时，脚和水的交线正确（说明 CPU/GPU 对齐了）
- [ ] FPS 下降不超过 30%

### 回滚

换回 Lit 材质即可，代码不动。

## 5. 阶段 3：泡沫

### 目标

岸线一圈不规则的白色泡沫，并且会随时间变化。

### 参考

**`IronWarrior/ToonWaterShader`（Unlicense，可以随便抄）**：

```
水深 = 场景深度 - 水面深度
泡沫 = smoothstep(0.0, _FoamDistance, 水深)
泡沫 *= 噪声(uv * scale + time)
```

### 步骤

1. 在 `WaterSurface.shader` 里加泡沫段
2. 两层噪声（tiling 4 / 12，速度不同）
3. 泡沫强度乘浪高（浪大泡沫多）
4. 用 `screenPos / screenPos.w` 采样深度，注意平台差异

### 产出

- `WaterSurface.shader` 增加 foam 分支
- `Textures/FoamNoise.png`（可平铺噪声）

### 验收

- [ ] 岸边有白边，边缘不规则
- [ ] 泡沫随浪起伏变化
- [ ] 远处不出现一条硬直线（深度精度问题）

### 回滚

`#define ENABLE_FOAM 0` 关掉。

## 6. 阶段 4：深度色 / 折射

### 目标

近岸清透见底，远处深蓝，水下物体有折射偏移。

### 参考

- 手册第 5 章（吸收 5 m、散射色、tip/body）
- `danielshervheim/unity-stylized-water` 的按深度混色

### 步骤

1. 加 `absorptionDistance`（Beer-Lambert）
2. 加 `scatteringColor` + `tip/body scattering`
3. 加屏幕空间折射（HDRP 的 `Custom Pass` 或 shader 里做 grab pass）
4. 三种水质预设（热带 / 温带 / 深海）

### 验收

- [ ] 站在浅水能看见沙子
- [ ] 深水是蓝黑色，不是均匀蓝
- [ ] 水下物体有轻微扭曲

## 8. 阶段 6：FFT 升级

### 目标

波形从 4 个 Gerstner 升级成 FFT 频谱，远景不再有重复感。

### 两条路

| 路线 | 成本 | 说明 |
|---|---|---|
| **A. 接 Unity HDRP Water System** | 低 | 已经有完整实现（三波段、泡沫、焦散），只需配置 |
| **B. 自己写 Compute Shader** | 高 | 抄 `Olof-AV/OceanWaterSim` 的结构 |

**推荐 A**：我们已经有 HDRP 17.3.0 的完整水系统，硬造没有意义。
把它包一层 `IWaterSimulation` 适配器，接口不变，外部零改动。

### 关键验收（这条最重要）

```
新增 FftWaterSimulation.cs
只改 WaterModule.Rebuild() 的一行
Player、Buoyancy、HUD 一行都不用动
```

**做不到这一点，说明模块化是假的，要回头改。**

## 9. 阶段 7：降级开关

### 为什么必须有

"最高档"在这台机器（2 核 + UHD 710）上跑不动。全部打开大约 5–10 FPS。

所以每个特性都要能单独关，做成三档预设：

| 特性 | LOW | MED | HIGH |
|---|---|---|---|
| 波形 | Gerstner 4 波 | Gerstner 4 波 | FFT 三波段 |
| 法线层数 | 1 | 2 | 2 + 细节 |
| 高光 | GGX | GGX | GGX + 时间抖动 |
| 泡沫 | ❌ | ✅ 单层噪声 | ✅ 双层 + 生命周期 |
| 深度色 | 简化 | ✅ | ✅ + 折射 |
| 反射 | ❌ | Reflection Probe | Probe + SSR |
| 焦散 | ❌ | ❌ | ✅ |
| 水下 | ❌ | ❌ | ✅ |

开关实现：`WaterSettings` 加一个 `QualityTier` 枚举，`WaterModule` 按档位改材质关键字。

### 验收

- [ ] LOW 能跑 25+ FPS
- [ ] HIGH 画面明显更好（但卡）
- [ ] 切换档位时不用重启

## 10. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| HDRP 在这台机器上编译 shader 极慢 | **高** | 用 HLSL 手写，少用 Shader Graph；改完一次编译等 2–5 分钟是常态 |
| 全部开满后 5 FPS，没法调 | **高** | 阶段 7 的降级开关提前到阶段 2 就做 |
| CPU/GPU 波形不同步 | 中 | 阶段 2 就把波参数统一到一个地方 |
| 深度纹理在某些平台不准 | 中 | 先只做 Windows |
| 抄来的代码版本太老（2018–2019） | 中 | 只抄思路和结构，API 用 Unity 6 的写法重写 |

### 阶段 6 为什么改方案

原计划是接 Unity HDRP Water System 或自己写 compute shader FFT。改成了 CPU 端频谱合成，理由：

1. **真正的 GPU FFT 需要三波段 + patch 平铺 + 多张 RT**，是一整套系统，
   自己写等于重造 HDRP Water System，和"不造轮子"冲突
2. **CPU 端做不到每帧 3 次逆 FFT 的性能**（这台 2 核机器更不行）
3. **"按频谱采样出一组波再直接求和"是逆 FFT 在采样点的逐点求值**，
   数学上等价、结果相同，只是省掉了 FFT 的加速结构
4. 复用了已经验证过的 Gerstner 采样路径，CPU/GPU 一致性不打折

**要真正的三波段 FFT**，正确做法是用 `WaterSurface` + `WaterSystem` 资产，
那是另一条工作线，不在本阶段范围。

### 没在 Unity 里跑过

全部代码只做了 **Roslyn 编译验证**（五个程序集全绿），shader 只做了括号/结构检查。
**第一次 Play 大概率要修**，按这个顺序排查：

1. 水面是粉红色 → shader 编译失败，看 Console 的 shader error
2. 水面全黑 → `_SunDirection` 或 `unity_SpecCube0` 没拿到
3. 水面看不见 → `SRPDefaultUnlit` 通道没被 HDRP 绘制（把 LightMode 改成 `Forward` 再试）
4. 画面和浮力错位 → CPU/GPU 波参数不同步，检查 `FillWaveData`
