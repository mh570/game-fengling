## 阶段 1.5：低分辨率像素渲染（2026-11-21 决定）

**为什么**：参考视频的"像素感"来自**低分辨率渲染 + 放大**，不是资产本身。
社区标准做法（retro post-process）：渲染到 480×270 的 RT，再用点采样放大到 1080p。

**好处**：任何低多边形资产都会自动变成阶梯状边缘，不需要买像素风资源包。

**做法**：
1. 管线里加一个低分辨率 RT（480×270）
2. 所有 pass 渲到这个 RT
3. 最后用 `FilterMode.Point` 放大到屏幕

**参数**：宽高比 16:9，基准 480×270（可配置 320×180 / 640×360）

**验证**：与参考帧对比，边缘应该出现同样的阶梯锯齿

## 2026-11-22 · 颜色精确对齐（实测校准）

**方法：渲染 → 采样 → 按差值调参 → 再渲染**，迭代 3 次。

**最终采样 vs 参考**：
| 部位 | 参考 | 我们 | 误差 |
|---|---|---|---|
| 树冠亮部 | `#8CA676` | **`#8BAB78`** | R+1, G+5, B+2 ✅ |
| 树干 | `#4A3540` | **`#4A3641`** | R0, G+1, B+1 ✅ |

**两个关键修复**：
1. **树干跳过叶片渐变**：用顶点色 alpha 当标记（树干 a=0，叶片 a=1），
   shader 里 `col = IN.color.a > 0.5 ? grad : float3(1,1,1)`
   —— 否则树干被叶片渐变染成绿色
2. **颜色全部按"线性→sRGB"反推**，再用实测差值迭代校准（不是理论值）

**但过度平滑了**：树冠成了塑料球，缺少参考的柔和斑驳质感。

**缺失的最后一条（已定位）**：`DrawLeaf.cs` 里每片叶子有**随机 `lightOffset`**：
```csharp
float lightOffset = Random.Range(0f, 1f);
if (LifhtOffsetDenesity < lightOffset) lightOffset = 0;
block.SetFloatArray("_lightOffset", lightOffset);
```
场景参数 `LightOffset: 0.396`
→ **每片叶子的明暗被随机扰动 0~0.396，产生柔和斑驳纹理。**

## 2026-11-22 · 树对齐完成（gamma 修正 + 卡片贴球面）

**两个决定性修复**：

### ① 色彩空间（gamma）
我们的颜色值是**线性空间**，显示转 sRGB 会开方变亮（0.43 → 0.69），
所以一直"发白/浅薄荷"。按 `sRGB^2.2` 反推后：
```csharp
_HighlightColor = (0.56, 0.69, 0.43)   // → sRGB #8CA676
_ShadowColor    = (0.17, 0.27, 0.16)   // → sRGB #64805A
```
**采样验证**：我们 `#87A57D` vs 参考 `#8CA676`，误差 < 5。

### ② 卡片位置（实心度）

## 2026-11-22 · 叶片环境光缺失（关键 bug）+ 色调对齐

**发现的关键 bug**：`ToonFoliage.shader` **完全没有环境光项**。
背光的叶片直接变黑 → 整棵树被拉暗 → 怎么调都发暗。

**修复**：


**配合的调色**：
| 项 | 值 |
|---|---|
| 顶点色三档 | `(0.58,0.78,0.44)` / `(0.68,0.86,0.52)` / `(0.80,0.94,0.62)` |

| `_ShadowColor` | `(0.46,0.58,0.46)` 提亮（低对比） |
| `_Cuts` | 3 → **8**（叶片要柔和，不是卡通分档） |

| 雾 | `Exponential 0.055`（大气透视） |

## 2026-11-22 · 找到 t3ssel8r 本人原话 + 均匀分布修正

**搜索到关键一手资料**：

**结论：我们的方法和他完全一致**（壳=shadow-caster，卡片=leaf sprites，球形法线=sphere normal）。

**关键收获**：他自己也承认第一版"太杂乱"，解法是**均匀分布（蓝噪声）**。

**我们的修正**（`TreeGenerator.cs`）：
```csharp
// Fibonacci 黄金角螺旋（比蓝噪声更简单，分布更均匀）
int perShell = leafCount / leafCenters.Count;
float y = 1f - (k + 0.5f) / perShell * 2f;
float rr2 = Mathf.Sqrt(Mathf.Max(0f, 1f - y * y));
float phi2 = k * 2.39996f;   // 黄金角
dir = (cos(phi2)*rr2, y, sin(phi2)*rr2);
// 再 + 0.18 抖动避免机械感
```

**参数**：卡片 2600→**9000 张**，尺寸 0.50→**0.15m**（细到糊在一起）

**结果**：树冠从"彩纸拼贴"变成"糊成一片的画"。
参考放大图：`Docs/images/t3ss/ref_canopy_zoom.png`（t3ssel8r 的树叶在最终分辨率下**看不见单张**）
结果：`Docs/images/t3ss/tree_fibonacci.png`

**遗留**：树冠中间的**壳球露出来了**（深色横带），需要让壳颜色和叶片一致。

## 2026-11-22 · 树干平面着色（3D 体积 + 2D 效果的统一原则）

**用户提问**：「怎么让树既有三维的体积感，又有二维的效果？树干呢」

**核心原则**（写进文档）：
```
形状 → 用 3D（几何、遮挡、投影、视差）
着色 → 用 2D（纯色块、硬边、像素、无渐变）

不要：3D 几何 + 平滑渐变着色（= 普通 3D）
不要：2D 贴图 + 无几何（= 纸片）
```

## 2026-11-22 · 树影修复（最关键的一步）

**问题**：树完全不投影，森林像漂浮的贴纸。

**根因**：`ToonFoliage.shader` 缺 **`CBUFFER_START(UnityPerMaterial)`**。
没有它，SRP Batcher 下材质属性声明不成立，采样宏展开错乱，
`SampleBias` / `SampleLevel` / `tex2D` 全部报 "no matching 0 parameter"。

**正确写法**（照抄本仓库的 `GrassBlade.shader`）：
```hlsl
sampler2D _MainTex;                       // 传统声明，不用 TEXTURE2D 宏

CBUFFER_START(UnityPerMaterial)           // ← 关键，之前缺这个
    float4 _MainTex_ST;
    float _Cutoff;
    half4 _BaseColor;
    ...
CBUFFER_END
```
ShadowCaster pass 同时 `#include Core.hlsl` + `Shadows.hlsl`，
用 `ApplyShadowBias` 朝光源偏移。

**结果**：✅ **每棵树在地上投下明确暗影**，森林终于"坐"在地上。

**这是两天以来观感提升最大的一次修改。** 图片：`Docs/images/t3ss/forest_with_shadows.png`

**详细文档**：`Docs/analysis/14-t3ssel8r管线.md`

**核心技术（已确认）**：
1. **5 步管线**：CopyColor → Downsample(640×360) → **Outline（在内部分辨率做，永远 1px）** → Composite → SharpUpscale
2. **描边两种边**：Silhouette（深度）+ Crease（**方向性对比**，不是 dot 求和）
3. **ToonLit**：Toon 分档 + **Patch 系统**（世界噪声色斑）+ 云影 + Bayer 抖动
4. **GrassBlade**：GPU Instancing ~35k 株，**颜色继承地形 patch 系统**（我们之前做错的点）
5. **像素完美平移**：相机吸附 texel 网格 + UV 偏移补偿
6. **不用 PBR**：纯色 + 调色板

**关键认知**：这套是**别人研究 t3ssel8r 后的成熟实现**，不是我们自己摸索。

```glsl
void vertex() {
    // 法线改成从树冠中心往外指 —— 卡片立刻有体积感
    vec3 spherical = normalize(VERTEX - canopy_center);
    NORMAL = normalize(mix(NORMAL, spherical, spherical_blend));
    // 风摆：低频整树摇 + 高频叶子抖
}
void light() {
    // 卡通量化：N·L 分 3 档
    DIFFUSE_LIGHT += ALBEDO * tinted * ATTENUATION * LIGHT_COLOR;
}
```

## 2026-11-21 · 树的尝试（受阻）

**发现的关键阻塞：glTF 导入不了**
```
Exception: glTFast: Unknown Render Pipeline
at GLTFast.RenderPipelineUtils.DetectRenderPipeline ()
```
`gltfast` 只认 Built-in / URP / HDRP，**不认识我们的自建 SRP**，所以 `.glb` 全部导入失败。
→ **Pixor 像素树（GLB）用不了**，除非换管线或转格式。

**改试 FBX**（Unity 原生导入，不依赖 gltfast）：
- 从 CC0Tree 复制了 `SM_Tree_Rounded.fbx`、`SM_Pine_Tree.fbx`、`SM_DeadPineTree.fbx`
- 代码日志显示"摆了 14 棵树"
- **但场景里实际是 0 棵**（`m_Name: Tree_` 匹配数为 0）

**推测原因**：`PrefabUtility.InstantiatePrefab` 对 FBX 模型资产实例化后，
在 `SaveScene` 时没有正确序列化进当前场景。

**结论**：树这块卡在两个技术阻塞上：
1. GLB 导入器不兼容自建 SRP
2. FBX 实例化后没存进场景

**下一步**：改用 `Object.Instantiate`（而非 PrefabUtility）+ `AddObjectToAsset`，
或者直接把树做成 prefab 资产再实例化。

## 2026-11-21 · GPU Instancing 草场（密度突破）

**目标**：视频的密度是 30×30 米里几千到上万株草，用 GameObject 不可能。

**实现**：
- `Fengling/Grass` shader：billboard 面片 + 根部到叶尖渐变 + 风摆
- `GrassField.cs`：`Graphics.RenderMeshInstanced` 批量画 **12000 株**，分 1023/批

**踩的 3 个坑**：
1. **`Material.enableInstancing = true` 必须开**，否则 `RenderMeshInstanced` 抛异常
2. **`Graphics.RenderMeshInstanced` 只在运行时调用**，编辑模式截图看不到 → 加 `[ExecuteAlways]`
3. **billboard shader 必须从实例矩阵取缩放**（`length(mul(m, float4(1,0,0,0)).xyz)`），否则每株都是 1×1 米铺满全屏
4. **静态 `TerrainCarver.Lakes` 在场景重载后丢失** → 草长到水里。改用 `Physics.Raycast` 打真实地面

**结果**：
- ✅ **12000 株草铺满 30×30m**，一次 draw call
- ✅ 水里不长草（射线判断）
- ✅ 沙滩带干净
- ⚠️ 水面平面边缘露出（方形平面 vs 圆形池塘）
- ⚠️ 没有白浪花边
- ⚠️ 草色偏亮、单一

**关键结论**：**密度可以做到了。** 现在 30×30 米的草量接近视频。

## 2026-11-21 · 分析"好看"的原理（文字版教程）

**产出**：`Docs/analysis/13-地形与画面好看的原理.md`（8 条原理 + 来源链接）

**最重要的三条**：

### P1 高度混合（Height-Based Blending）
> "用高度图把上层材料推到下层上面——例如**岩石从草丛里突出来**。"

我们现在顶点色是**线性插值**，过渡是一条平直渐变带。
应该改成**交界处用噪声决定谁在上** → 不规则锯齿边界。

### P5 阴影不能是纯黑
> "阴影颜色不该只是加黑，那会让物体看起来**没有生命**。"

**这解释了参考视频里树影是深绿而不是黑色。**
我们的 `PlayerBlobShadow` 现在是黑色椭圆 → 应改成深绿。

### P7 颜色校正
> "通过精细的颜色校正，每一束光都被调过，塑造出丰盛感。" —— Ubisoft

我们**完全没有颜色校正**，这是"看起来业余"的一大原因。

**其它原理**：
- P2 三平面映射（陡坡不拉伸贴图）
- P3 调色板统一
- P4 植被铺满 > 地形细节
- P6 大气透视（雾色 = 天空色）
- P8 避免过曝（中间调才有色彩）

**核心结论**：
> "好看"不是把每个东西做得更精细，而是让所有东西**看起来属于同一个世界**。
> 我们缺的不是技术，是这四条：色彩统一、阴影有颜色、远景化入空气、地面被植物盖住。

## 2026-11-21 · 地形"裂缝"真因定位

**决定性实验**：`heightmapPixelError = 1`（几乎不降 LOD）→ **画面完全没变**。
→ **不是 LOD 接缝。**

**看图得出的结论**：那些"悬浮绿色矩形"和"阶梯错位"是**整块平移**，边缘是直边、整块错开，
不是 LOD 的锯齿过渡。

**真因**：**地形块的顶点空间不匹配**
- Unity Terrain 的顶点已经是世界坐标（或用 per-chunk 矩阵）
- 我们的 `FenglingLit` 用 `UnityObjectToClipPos(v.vertex)` 又变换了一次
- → 每个地形块被推到不同位置，看起来像"悬浮的方块"

**修法**：地形的 shader 要用地形专用的顶点函数（参考 URP/HDRP 的 `TerrainVertex`，
用 `_TerrainTiles` / `UNITY_TERRAIN` 相关宏），不能复用普通物体的顶点路径。

**顺带验证**：`terrain.drawInstanced = true` 会让地形**完全消失**（我们的 shader 没有 instancing 支持）。

## 2026-11-21 · 法线 pass 第二次失败 → 改方案

**第二次尝试**：法线 pass 不调 `Submit()`，加调试 Blit 直接显示法线 RT。
**结果**：仍然整屏红 `(255,0,0)`。**已回滚**。

**诊断**：问题在**时序**——`context.DrawRenderers` 是排在 context 命令流里、尚未提交时，我就用 `CommandBuffer.Blit` 读那张 RT，读到的是未绘制内容。

**改用正统方案（见 Unity 官方文档）**：

> "如果采用自定义 SRP，并且不想在着色器中实现 DepthNormals Pass，则可以使用深度纹理来重建法线矢量"
> —— [Unity 手册](https://docs.unity.cn/cn/current/Manual/urp/post-processing-ssao.html)

**即：不加法线 pass，直接在描边 shader 里用深度重建法线**：

```hlsl
float3 ReconstructNormal(float2 uv, float depth)
{
    float2 t = _FenglingSceneDepth_TexelSize.xy;
    float dx = Depth(uv + float2(t.x,0)) - depth;
    float dy = Depth(uv + float2(0,t.y)) - depth;
    return normalize(float3(-dx, -dy, t.x));   // 简易重建
}
```

**好处**：不需要额外 RT、不需要改所有 shader、没有时序问题。

**下一步**：把描边 shader 改成"深度 + 深度重建法线"。

## 2026-11-21 · 阶段重排（基于 01/02 视频分析）

**本次提交**：完成 01（水与鱼）、02（树）分析，据此重排优先级

**关键发现 —— 跨两个视频的共同签名**：

> **白色亮线描边**：水里画在岸线上，林里画在路面/台阶/石头边缘。
> 这是让画面有"手绘插画感"的最强特征，而且实现成本很低（深度差/法线差的边缘检测）。

**重排后的优先级**：

| 序 | 任务 | 为什么排这里 | 成本 |
|---|---|---|---|
| 1 | **边缘亮线后处理** | 两视频共同签名，视觉冲击最大 | 小 |
| 2 | **水的浅/深双色 + 岸线白边** | 水是画面主体，白边也在这一项里 | 小~中 |
| 3 | 地形 shader（修洋红） | 当前地形是洋红，挡路 | 中 |
| 4 | 树（团簇 + 轮廓光）+ 假影子 | 内容层缺口最大 | 中 |
| 5 | 低分辨率像素渲染 | 统一画面质感 | 小 |
| 6 | 面片光柱 | 氛围高峰 | 中 |
| 7 | 体积云穿光 | 依赖光柱 | 大 |

**相比原计划的变化**：原本把"地形 shader"排第一，现在**边缘亮线和水的双色提到最前**——因为它们成本更小、观感提升更直接，且不依赖地形。

**其它发现**：
- 水色靠**深度**插值，不是菲涅尔
- 树冠有**轮廓光**（菲涅尔边缘），这是树"跳出来"的关键
- 树用**假影子**（椭圆暗斑），不是精确阴影
