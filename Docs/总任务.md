## 阶段 1.5：低分辨率像素渲染（2026-11-21 决定）

**为什么**：参考视频的"像素感"来自**低分辨率渲染 + 放大**，不是资产本身。
社区标准做法（retro post-process）：渲染到 480×270 的 RT，再用点采样放大到 1080p。

**好处**：任何低多边形资产都会自动变成阶梯状边缘，不需要买像素风资源包。

**做法**：
1. 管线里加一个低分辨率 RT（480×270）
2. 所有 pass 渲到这个 RT
3. 最后用 `FilterMode.Point` 放大到屏幕

**参数**：宽高比 16:9，基准 480×270（可配置 320×180 / 640×360）

**验证**：与参考帧对比，边缘应该出现同样的阶梯锯齿

## 阶段 2：地表与植被

# 四、进度快照（每次提交更新）

## 2026-11-21 · 法线 pass 第二次失败 → 改方案

**第二次尝试**：法线 pass 不调 `Submit()`，加调试 Blit 直接显示法线 RT。
**结果**：仍然整屏红 `(255,0,0)`。**已回滚**。

**诊断**：问题在**时序**——`context.DrawRenderers` 是排在 context 命令流里、尚未提交时，我就用 `CommandBuffer.Blit` 读那张 RT，读到的是未绘制内容。

**改用正统方案（见 Unity 官方文档）**：

> "如果采用自定义 SRP，并且不想在着色器中实现 DepthNormals Pass，则可以使用深度纹理来重建法线矢量"
> —— [Unity 手册](https://docs.unity.cn/cn/current/Manual/urp/post-processing-ssao.html)

**即：不加法线 pass，直接在描边 shader 里用深度重建法线**：

```hlsl
float3 ReconstructNormal(float2 uv, float depth)
{
    float2 t = _FenglingSceneDepth_TexelSize.xy;
    float dx = Depth(uv + float2(t.x,0)) - depth;
    float dy = Depth(uv + float2(0,t.y)) - depth;
    return normalize(float3(-dx, -dy, t.x));   // 简易重建
}
```

**好处**：不需要额外 RT、不需要改所有 shader、没有时序问题。

**下一步**：把描边 shader 改成"深度 + 深度重建法线"。

## 2026-11-21 · 阶段重排（基于 01/02 视频分析）

**本次提交**：完成 01（水与鱼）、02（树）分析，据此重排优先级

**关键发现 —— 跨两个视频的共同签名**：

> **白色亮线描边**：水里画在岸线上，林里画在路面/台阶/石头边缘。
> 这是让画面有"手绘插画感"的最强特征，而且实现成本很低（深度差/法线差的边缘检测）。

**重排后的优先级**：

| 序 | 任务 | 为什么排这里 | 成本 |
|---|---|---|---|
| 1 | **边缘亮线后处理** | 两视频共同签名，视觉冲击最大 | 小 |
| 2 | **水的浅/深双色 + 岸线白边** | 水是画面主体，白边也在这一项里 | 小~中 |
| 3 | 地形 shader（修洋红） | 当前地形是洋红，挡路 | 中 |
| 4 | 树（团簇 + 轮廓光）+ 假影子 | 内容层缺口最大 | 中 |
| 5 | 低分辨率像素渲染 | 统一画面质感 | 小 |
| 6 | 面片光柱 | 氛围高峰 | 中 |
| 7 | 体积云穿光 | 依赖光柱 | 大 |

**相比原计划的变化**：原本把"地形 shader"排第一，现在**边缘亮线和水的双色提到最前**——因为它们成本更小、观感提升更直接，且不依赖地形。

**其它发现**：
- 水色靠**深度**插值，不是菲涅尔
- 树冠有**轮廓光**（菲涅尔边缘），这是树"跳出来"的关键
- 树用**假影子**（椭圆暗斑），不是精确阴影
