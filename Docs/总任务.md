## 阶段 1.5：低分辨率像素渲染（2026-11-21 决定）

**为什么**：参考视频的"像素感"来自**低分辨率渲染 + 放大**，不是资产本身。
社区标准做法（retro post-process）：渲染到 480×270 的 RT，再用点采样放大到 1080p。

**好处**：任何低多边形资产都会自动变成阶梯状边缘，不需要买像素风资源包。

**做法**：
1. 管线里加一个低分辨率 RT（480×270）
2. 所有 pass 渲到这个 RT
3. 最后用 `FilterMode.Point` 放大到屏幕

**参数**：宽高比 16:9，基准 480×270（可配置 320×180 / 640×360）

**验证**：与参考帧对比，边缘应该出现同样的阶梯锯齿

## 2026-11-21 · 分析"好看"的原理（文字版教程）

**产出**：`Docs/analysis/13-地形与画面好看的原理.md`（8 条原理 + 来源链接）

**最重要的三条**：

### P1 高度混合（Height-Based Blending）
> "用高度图把上层材料推到下层上面——例如**岩石从草丛里突出来**。"

我们现在顶点色是**线性插值**，过渡是一条平直渐变带。
应该改成**交界处用噪声决定谁在上** → 不规则锯齿边界。

### P5 阴影不能是纯黑
> "阴影颜色不该只是加黑，那会让物体看起来**没有生命**。"

**这解释了参考视频里树影是深绿而不是黑色。**
我们的 `PlayerBlobShadow` 现在是黑色椭圆 → 应改成深绿。

### P7 颜色校正
> "通过精细的颜色校正，每一束光都被调过，塑造出丰盛感。" —— Ubisoft

我们**完全没有颜色校正**，这是"看起来业余"的一大原因。

**其它原理**：
- P2 三平面映射（陡坡不拉伸贴图）
- P3 调色板统一
- P4 植被铺满 > 地形细节
- P6 大气透视（雾色 = 天空色）
- P8 避免过曝（中间调才有色彩）

**核心结论**：
> "好看"不是把每个东西做得更精细，而是让所有东西**看起来属于同一个世界**。
> 我们缺的不是技术，是这四条：色彩统一、阴影有颜色、远景化入空气、地面被植物盖住。

## 2026-11-21 · 修缺口 + 修台地

**缺口的原因**：
- 之前用 Sebastian Lague 的**边框扩展**做法，但那是给 **LOD 过渡**用的
- 我们在 LOD0（各块同分辨率）下用边框反而引入了错位 → 缺三角形
- **正确做法**：同分辨率时相邻块**共享完全相同的边缘顶点**（采样函数确定 ⇒ 天然水密）

**台地的原因**：平滑半径太小（4）+ 压平太浅（35%）
- 改为平滑半径 **10**、压平 **28%**

**同时修掉一个严重 bug**：新生成器输出**世界坐标**，场景脚本又加了块偏移 → 地形被推到画面外（截图全空）

**结果**：
- ✅ 缺口没了
- ✅ 台地没了
- ✅ 表面平滑
- ⚠️ **压得太平**（几乎看不出起伏，像一块绿毯）

**下一步**：压平参数回调到 0.5~0.6，找回一点起伏但不要台地。

## 2026-11-21 · 修复坐标系 bug（分带范围错误）

**根因**：`WorldOrigin` 的约定不一致
- `TerrainMeshBuilder.Build` 把它当**左下角**（origin + i*cell）
- `TerrainSceneBuilder` 把它当**中心**（origin + x，x 从 -100 到 100）

→ 生成的地形和相机/扫描差了 100 米，分带范围算成 0~100（实际 -50~59）。

**修复**：
- `FindBestRegion` 返回值从"中心"改成"左下角"（`cx - halfSize`）
- 场景脚本的高度扫描改为围绕 `origin + 100` 的中心

**结果**：
- 分带范围 `-50.0 ~ 59.0` 与区域高度一致 ✅
- **画面出现大片绿色草地 + 抖动纹理 + 台地地形** ✅

**遗留**：
- 1m 采样下的陡坡仍是"台地"状（视频里的地更平缓）
- 画面仍偏灰白
- 地形无阴影

## 2026-11-21 · 地形"裂缝"真因定位

**决定性实验**：`heightmapPixelError = 1`（几乎不降 LOD）→ **画面完全没变**。
→ **不是 LOD 接缝。**

**看图得出的结论**：那些"悬浮绿色矩形"和"阶梯错位"是**整块平移**，边缘是直边、整块错开，
不是 LOD 的锯齿过渡。

**真因**：**地形块的顶点空间不匹配**
- Unity Terrain 的顶点已经是世界坐标（或用 per-chunk 矩阵）
- 我们的 `FenglingLit` 用 `UnityObjectToClipPos(v.vertex)` 又变换了一次
- → 每个地形块被推到不同位置，看起来像"悬浮的方块"

**修法**：地形的 shader 要用地形专用的顶点函数（参考 URP/HDRP 的 `TerrainVertex`，
用 `_TerrainTiles` / `UNITY_TERRAIN` 相关宏），不能复用普通物体的顶点路径。

**顺带验证**：`terrain.drawInstanced = true` 会让地形**完全消失**（我们的 shader 没有 instancing 支持）。

## 2026-11-21 · 法线 pass 第二次失败 → 改方案

**第二次尝试**：法线 pass 不调 `Submit()`，加调试 Blit 直接显示法线 RT。
**结果**：仍然整屏红 `(255,0,0)`。**已回滚**。

**诊断**：问题在**时序**——`context.DrawRenderers` 是排在 context 命令流里、尚未提交时，我就用 `CommandBuffer.Blit` 读那张 RT，读到的是未绘制内容。

**改用正统方案（见 Unity 官方文档）**：

> "如果采用自定义 SRP，并且不想在着色器中实现 DepthNormals Pass，则可以使用深度纹理来重建法线矢量"
> —— [Unity 手册](https://docs.unity.cn/cn/current/Manual/urp/post-processing-ssao.html)

**即：不加法线 pass，直接在描边 shader 里用深度重建法线**：

```hlsl
float3 ReconstructNormal(float2 uv, float depth)
{
    float2 t = _FenglingSceneDepth_TexelSize.xy;
    float dx = Depth(uv + float2(t.x,0)) - depth;
    float dy = Depth(uv + float2(0,t.y)) - depth;
    return normalize(float3(-dx, -dy, t.x));   // 简易重建
}
```

**好处**：不需要额外 RT、不需要改所有 shader、没有时序问题。

**下一步**：把描边 shader 改成"深度 + 深度重建法线"。
